# RegWatch

Multi-tenant compliance monitoring SaaS for Indian NBFCs. Tracks regulatory updates from RBI, SEBI, IRDAI, and MCA — with AI-powered impact analysis, a live compliance dashboard, and daily email digests.

## Architecture

```
compliance-agent/
├── backend/          # FastAPI app (Python 3.12+)
│   ├── app/
│   │   ├── main.py           # FastAPI entry point, serves React SPA
│   │   ├── config.py         # Pydantic settings (reads backend/.env)
│   │   ├── database.py       # SQLAlchemy engine
│   │   ├── models/           # ORM models: org, user, update
│   │   ├── routers/          # API routes: auth, admin, updates
│   │   ├── services/
│   │   │   ├── scraper.py    # Orchestrates all parsers
│   │   │   ├── parsers/      # Per-regulator HTML scrapers
│   │   │   ├── analyzer.py   # AI analysis (Ollama or rule-based fallback)
│   │   │   ├── llm/          # LLM abstraction layer
│   │   │   ├── digest.py     # Email digest builder + Brevo sender
│   │   │   └── scheduler.py  # APScheduler background jobs
│   │   └── auth/             # bcrypt + itsdangerous session tokens
│   ├── migrations/           # SQL schema (001_initial.sql)
│   ├── tests/                # pytest suite
│   ├── static/               # Built React app (git-ignored, generated by npm run build)
│   ├── requirements.txt
│   └── .env                  # Local secrets (never committed)
├── frontend/         # React 18 + TypeScript + Vite
│   ├── src/
│   │   ├── pages/            # DashboardPage, AdminPage, LoginPage
│   │   ├── components/       # UpdateCard, DetailModal, Sidebar, MetricStrip, …
│   │   ├── hooks/            # useAuth, useUpdates
│   │   ├── api/              # Axios client + TypeScript types
│   │   └── theme.ts          # Design tokens (slate/indigo dark theme)
│   └── vite.config.ts        # Build output → ../backend/static
├── legacy/           # Original Streamlit prototype (not active)
├── Dockerfile        # Multi-stage: Node build → Python serve
└── render.yaml       # Render.com deployment config
```

## Local development

### Prerequisites
- Python 3.12+
- Node 20+

### Backend

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Create `backend/.env`:
```
DATABASE_URL=sqlite:///./regwatch_dev.db
SECRET_KEY=change-me-in-production
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=llama3.1:8b
BREVO_API_KEY=
SENDER_EMAIL=
FETCH_SCHEDULE_HOURS=6
DIGEST_TIME_IST=08:00
```

Start the server:
```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev          # dev server on :5173 with proxy to :8000
```

Or build and serve from the backend (production mode):
```bash
cd frontend && npm run build    # writes to backend/static/
# then open http://localhost:8000
```

### Create first organisation + admin user

```bash
curl -X POST http://localhost:8000/admin/orgs \
  -H "Content-Type: application/json" \
  -d '{
    "name": "My NBFC",
    "nbfc_type": "NBFC-ICC",
    "admin_email": "admin@mynbfc.com",
    "admin_password": "changeme"
  }'
```

### Trigger a data fetch

Log in at `http://localhost:8000`, go to **Admin → Data Pipeline → Trigger Manual Fetch**.

## AI analysis

By default, analysis uses a rule-based `TemplateProvider` (no LLM required). To enable real AI analysis via Ollama:

```bash
docker run -d -v ollama:/root/.ollama -p 11434:11434 ollama/ollama
docker exec <container> ollama pull llama3.1:8b
```

The backend auto-detects Ollama on startup and switches providers.

## Email digest

Add Brevo credentials to `backend/.env`:
```
BREVO_API_KEY=your-key
SENDER_EMAIL=your-verified-sender@domain.com
```

Get a free key at [brevo.com](https://brevo.com) (300 emails/day free tier). Use **Admin → Daily Email Digest → Preview Email** to verify the HTML before sending.

## Deployment (Render.com)

Push to GitHub, then create a new Render service:

1. Connect your GitHub repo
2. Render detects the `Dockerfile` automatically
3. Add a Postgres database — `render.yaml` links it automatically
4. Set `BREVO_API_KEY` and `SENDER_EMAIL` as environment variables
5. Deploy

For PostgreSQL in production, replace the `SQLite` driver with the `DATABASE_URL` Render provides. Run `migrations/001_initial.sql` against the database once.
